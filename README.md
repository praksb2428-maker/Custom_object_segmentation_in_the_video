# 사용자 선택 기반 영상 객체 분할·추적

영상에서 사용자가 고른 물체를 SAM 2.1로 분할하고, 그 물체가 움직이는 모습을 배경 없이 저장하는 파이썬 프로젝트입니다. 이미 학습된 모델을 사용하며 새 모델을 학습시키지 않습니다.

## 순서대로 실행하기

아래 명령은 이 프로젝트 폴더에서 PowerShell로 실행합니다. 다른 장비로 옮길 때는 실행 환경을 새로 구성하고 드라이버와 PyTorch 호환성을 확인해야 합니다.

VS Code에서는 프로젝트의 `.venv` Python을 선택한 뒤 `main.py`를 열고 **Run Python File in Terminal(▶)**을 눌러 실행할 수 있습니다. 인자를 지정하지 않으면 이 파일이 있는 프로젝트의 `input/sample.mp4`를 사용하고, 작은 물체 다중 선택·추적, 이동 경로 표시, 투명 PNG 저장을 켜서 앞 60초를 처리합니다. 결과는 `outputs/selected-...`의 새 폴더에 저장되고 터미널에 경로가 표시됩니다. 터미널의 현재 폴더가 달라도 기본 입력·출력 경로는 프로젝트 기준입니다. 기존 `run`, `select`, `evaluate` 명령과 `run_sample.cmd`도 계속 사용할 수 있습니다.

### 준비

Python 3.12와 Git이 필요합니다. 가상환경은 이 프로젝트에만 설치됩니다. 모델 가중치와 PyTorch를 내려받으므로 디스크 공간과 인터넷 연결이 필요합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128
$env:SAM2_BUILD_CUDA = '0'
.\.venv\Scripts\python.exe -m pip install wheel
.\.venv\Scripts\python.exe -m pip install --no-build-isolation -r requirements.txt -r requirements-sam2.txt
.\.venv\Scripts\python.exe tools/download_model.py --model small
```

Windows에서는 SAM 2의 선택적 CUDA 확장 빌드를 생략합니다. 모델 자체는 CUDA로 실행할 수 있습니다. 공식 안내는 [SAM 2 저장소](https://github.com/facebookresearch/sam2)에서 확인할 수 있습니다. 이 코드는 위 고정 리비전의 영상 예측 API를 사용합니다.

### 1. 물체 하나부터 분할하기

`input` 폴더에 직접 촬영했거나 사용 허가를 확인한 짧은 MP4를 `sample.mp4`로 넣습니다.

```powershell
.\.venv\Scripts\python.exe main.py run --video input/sample.mp4 --output outputs/single --single
```

첫 화면에서 물체를 선택하고 Enter를 누르면 분할이 시작됩니다. 기본적으로 영상의 앞 1분(60초)을 처리하며, 1분보다 짧으면 전체를 처리합니다. FPS에 맞춰 30fps 영상은 최대 1,800프레임, 60fps 영상은 최대 3,600프레임을 사용합니다. 다른 길이는 `--max-seconds 30`, 프레임 수 직접 지정은 `--max-frames 300`, 전체 처리는 `--all-frames`를 추가합니다. 세 옵션은 함께 사용할 수 없습니다. `run_sample.cmd`에도 같은 기본 제한이 적용됩니다. 1분은 처리 대상 영상 길이이며 프로그램 실행 시간이 아닙니다. 물체 수와 영상 크기에 따라 처리 시간·메모리·저장 공간이 늘어납니다.

### 2. 여러 물체 선택하기

```powershell
.\.venv\Scripts\python.exe main.py run --video input/sample.mp4 --output outputs/multi
```

최대 **3개**까지 선택할 수 있습니다. 선택 창에 포커스를 둔 상태에서 숫자 **1**을 누르고 첫 물체를 마우스로 선택하고, **2**를 누르고 두 번째 물체를 선택하고, **3**을 누르고 세 번째 물체를 선택합니다. 숫자는 편집할 객체 ID를 바꾸는 키이며 마우스 클릭·드래그·휠 동작은 그대로입니다. 다른 번호로 옮겨도 기존 선택은 유지되고, 같은 번호를 다시 눌러 그 객체의 박스나 점을 수정할 수 있습니다. 번호 순서대로 선택할 필요는 없으며, 비어 있는 번호는 처리하지 않습니다. **Enter**를 누르면 선택한 1~3개를 함께 처리합니다. 선택이 잘못됐으면 안내를 표시하고 선택 화면을 유지하므로 해당 번호로 돌아가 수정할 수 있습니다. 기존 **N 또는 스페이스**로 다음 객체를 고르는 방식도 사용할 수 있으며, 세 번째에서 다음 키를 눌러도 네 번째 객체는 추가되지 않습니다. 화면에 현재 편집 중인 객체 번호와 선택 수가 표시되고 각 객체는 서로 다른 색상과 ID로 구분됩니다. 자동으로 모든 물체를 찾아주는 기능은 아닙니다. 저장한 선택 파일도 최대 3개까지만 허용합니다. `--single`에서는 객체 1만 선택할 수 있습니다.

### 3. 작은 물체를 확대해서 선택하기

마우스 휠로 해당 위치를 확대하고 박스 또는 점을 지정합니다. 선택 좌표는 원래 영상 좌표로 바뀌어 모델에 전달됩니다. 확대는 클릭을 돕는 기능이며 원본에 없던 세부 정보를 복원하지는 않습니다.

작은 물체 추적 모드는 `--small-objects`를 추가합니다. `run_sample.cmd`에는 이 옵션이 기본 적용되어 있습니다.

```powershell
.\.venv\Scripts\python.exe main.py run --video input/sample.mp4 --output outputs/small-test --small-objects --tracks --transparent
```

기본 `continuous` 방식은 전체 화면의 문맥을 유지하고 선택한 물체 1~3개를 같은 SAM 영상 메모리에서 추적합니다. 물체 주변만 잘라 짧은 간격으로 새로 선택하던 방식에서 배경이 다음 선택에 섞이는 문제를 줄이기 위한 방식입니다. 전체 화면을 입력하므로 아주 작은 물체의 세부 모양까지 보장하지는 않습니다. 결과 좌표와 영상 크기는 원본과 같습니다.

긴 영상을 한 번에 모델에 올리지 않고 48개 출력 프레임씩 처리합니다. 다음 구간에는 물체별 마지막 유효 마스크와 해당 프레임을 전달합니다. 가림 복구용 과거 프레임을 포함해 모델에 올리는 입력은 한 구간당 최대 108프레임(48+기본 복구 60)입니다. 원본 JPEG의 디코딩 캐시는 최대 16장·128MiB이며 정상 종료와 오류 때 비웁니다. 이 수치는 모델 전체나 GPU 메모리 사용량의 상한을 뜻하지 않습니다.

이전 이동 영역 방식은 `--small-objects --tracking-backend local`로 비교할 수 있습니다. 이때만 `--crop-size 128`, `--crop-size 384`처럼 물체 주변 입력 크기를 바꿉니다. 기본값은 256픽셀이며 큰 선택 박스는 영역이 자동으로 커집니다. 기본 연속 추적에서는 `--crop-size`를 사용하지 않습니다.

이 모드는 마지막으로 추적한 대상 주변에 있는 SAM 분할 조각들을 함께 유지합니다. 프레임 사이에 물체가 빠르게 이동하면, 대상 안의 특징점 이동을 광학 흐름으로 추정해 이전 마스크의 비교 위치를 옮깁니다. 정방향·역방향 추적이 맞는지와 특징점들의 이동이 일관적인지 검사하고, 추정이 불확실하면 기존 위치 기준으로 검사합니다. 이동시킨 이전 마스크는 비교에만 사용하고 저장되는 분할 영역은 SAM이 실제로 출력한 픽셀에서만 가져옵니다. 다른 물체로 잘못 넘어가는 오류를 완전히 방지하는 신원 확인 기능은 아닙니다.

캐릭터 앞의 글자 등으로 몸이 여러 조각으로 나뉘어도 조각 하나만 남기는 방식으로 처리하지 않습니다. 대상 주변의 배경 조각을 잘못 포함할 가능성은 있으며, 가려진 부분을 임의로 채우지는 않습니다. 화면 밖으로 나간 물체는 분할할 수 없습니다.

잠깐 인식하지 못한 프레임은 `missing` 상태와 빈 마스크로 기록하고, 프로그램 기본 실행에서는 최대 60프레임 동안 같은 SAM 추적 및 마지막 유효 영역을 기준으로 복구를 시도합니다. 60fps 영상은 약 1초, 30fps 영상은 약 2초이며 처리 시간을 늘리는 설정입니다. 다시 인식하면 `recovered`로 기록합니다. `--recovery-frames 12`처럼 1~60 범위에서 직접 조정할 수 있습니다. 지정한 프레임 수만큼 연속 실패하면 `lost`로 기록하고 이후 마스크는 비웁니다. 첫 프레임부터 대상이 검출되지 않으면 바로 놓침 처리합니다. 최종 `lost` 뒤 장시간 가림이나 화면 밖 이동에서 자동 재발견하는 기능은 없습니다. 복구 역시 동일 물체임을 보장하는 신뢰도 판정이 아닙니다.

연속 추적에서는 처음 채택한 물체의 색 분포를 기준으로 유지합니다. 이후 결과의 색이 크게 달라지면 손이나 다른 배경으로 바뀌었을 가능성이 있어 빈 마스크로 기록하고 복구를 기다립니다. 가림 뒤 가까운 영역으로 돌아온 경우에도 위치·크기·처음 색 분포를 함께 확인합니다. 4픽셀 미만의 초기 마스크에는 색 검사를 적용할 정보가 부족합니다. 실제 물체의 색이나 조명이 급변하면 복구하지 못할 수 있고, 비슷한 물체끼리는 잘못 이어질 수 있습니다. 화면에 보이지 않는 물체를 임의로 그려 넣지는 않습니다.

`run.json`의 `completed`는 저장 완료이며 모든 물체의 추적 성공을 뜻하지 않습니다. `lost_object_ids`, 일시 실패가 있었던 `missing_object_ids`, `tracking_status.csv`를 함께 확인하세요. `tracked` 역시 정확도 점수가 아닌 프로그램 상태입니다. CSV에는 연속 실패 수와 모델 영역·채택 영역의 면적도 기록합니다.

배경의 작은 조각으로 추적이 바뀌는 현상을 줄이기 위해, 지금까지 채택한 가장 큰 마스크 면적의 20% 미만은 놓침으로 처리합니다. 기준 면적은 정상적으로 커진 마스크에 맞춰 갱신하므로 카메라가 서서히 확대되는 상황을 허용합니다. 단, 이전 마스크에 비해 한 번에 8배 초과로 커지거나 1/8 미만으로 작아지면 제외합니다. 실제 물체가 크게 멀어지거나 급격히 크기가 바뀌어도 중단될 수 있습니다. 가림·동일 크기의 다른 물체로 전환되는 오류를 완전히 판별하는 기능은 아닙니다.

**1 / 2 / 3**으로 객체 번호를 고른 뒤 물체마다 박스를 작게 그리세요. 마지막에는 Enter로 완료합니다. 여러 번 왼쪽 클릭하면 현재 번호의 객체에 포함 지점만 추가됩니다. 오른쪽 클릭은 배경 제외입니다. 시작 전에 등록된 물체 수가 터미널에 표시됩니다.

| 조작 | 기능 |
|---|---|
| 왼쪽 드래그 | 물체를 둘러싼 박스 |
| 왼쪽 클릭 | 포함할 물체 지점 |
| 오른쪽 클릭 | 제외할 배경 지점 |
| 마우스 휠 | 확대·축소 |
| 1 / 2 / 3 | 편집할 객체 ID 선택, 이전 객체 수정 가능 |
| R / U | 확대 초기화 / 현재 물체 선택 취소 1회 |
| N 또는 스페이스 / Enter / Esc | 다음 물체(최대 3개) / 선택 완료 / 종료 |

박스와 점을 함께 사용할 수 있습니다. 이 버전은 **첫 프레임에서 보이는 물체**만 선택합니다. 중간 프레임에서 선택을 고치는 기능은 아직 없습니다.

### 4. 마스크 보정과 이동 경로

```powershell
.\.venv\Scripts\python.exe main.py run --video input/sample.mp4 --output outputs/cleaned --fill-holes 8 --tracks --transparent
```

`--fill-holes 8`은 물체 내부의 8픽셀 이하 구멍만 채웁니다. `--min-area 5`는 5픽셀 미만의 분리된 부분을 지웁니다. 작은 물체까지 지워질 수 있으므로 잡음 제거는 기본적으로 꺼져 있습니다. 보정이 정확도를 반드시 높이는 것은 아닙니다.

같은 선택으로 전후를 비교하려면 먼저 선택을 저장합니다.

```powershell
.\.venv\Scripts\python.exe main.py select --video input/sample.mp4 --save input/selection.json
.\.venv\Scripts\python.exe main.py run --video input/sample.mp4 --prompts input/selection.json --output outputs/comparison --fill-holes 8 --tracks
```

### 5. 정확도 비교하기

영상의 몇 프레임을 골라 사람이 직접 물체 영역을 표시한 정답 PNG를 준비합니다. 배경은 0, 물체는 255인 단일 채널 PNG여야 합니다. 추론 입력으로 쓴 선택 박스는 정답 마스크가 아닙니다.

```text
input/truth/
  object_1/000000.png
  object_1/000010.png
  object_2/000000.png
  object_2/000010.png
```

```powershell
.\.venv\Scripts\python.exe main.py evaluate --predictions outputs/comparison/masks_raw --truth input/truth --csv outputs/raw-evaluation.csv
.\.venv\Scripts\python.exe main.py evaluate --predictions outputs/comparison/masks --truth input/truth --csv outputs/cleaned-evaluation.csv
```

IoU와 Dice는 예측 영역과 정답 영역이 얼마나 겹치는지 나타냅니다. 1에 가까울수록 잘 맞습니다. 정답이 있는 프레임만 평가하며 예측 파일이 빠지면 오류를 냅니다. 정답·예측이 모두 비어 있으면 1로 계산하므로 물체가 실제로 보이는 프레임의 점수도 따로 출력합니다.

## 결과 파일

| 파일·폴더 | 내용 |
|---|---|
| `foreground.mp4` | 선택한 물체만 보이는 영상, 배경은 검정 |
| `overlay.mp4` | 원본 위에 분할 영역 표시, 선택 시 이동 경로 포함 |
| `masks_raw`, `masks` | 물체 ID별 원본·보정 마스크 PNG |
| `transparent` | `--transparent` 사용 시 물체 ID별 투명 PNG |
| `centroids.csv` | 물체 중심 좌표와 면적, 사라지면 중심은 빈 값 |
| `prompts.json` | 첫 프레임의 선택 좌표 |
| `run.json` | 정상 완료 기록, 입력·모델 해시와 실행 시간 |
| `tracking_status.csv` | 작은 물체 모드에서 ID별 추적/놓침 상태와 분석 영역 |
| `frames` | 모델 입력으로 사용한 JPEG 프레임 |

MP4에는 투명 배경과 원래 음성이 들어가지 않습니다. 여러 물체가 선택되면 `foreground.mp4`에는 그 물체들이 함께 보이고, 마스크와 투명 PNG는 각각 저장됩니다. 물체는 원래 영상의 움직임을 유지합니다. 물체를 원하는 방향으로 새롭게 움직이게 하는 애니메이션 편집 기능은 아닙니다.

기존 결과 폴더와 파일은 덮어쓰지 않습니다. 실패한 출력 폴더는 확인용으로 남으며 `run.json`이 없습니다. 다시 실행할 때는 새 출력 폴더 이름을 사용하세요.

## 프로젝트 범위와 제한

- 작은 물체, 흐림, 가림, 비슷한 배경에서는 분할이 틀릴 수 있습니다. 모든 세부 영역의 동시 분할을 보장하지 않습니다.
- 전체 프레임 기본 모드, 복구와 입력 구간 제한을 적용한 연속 추적, 이전 물체별 이동 영역 방식을 지원합니다. 기본 실행은 연속 추적입니다. 이동 영역 방식은 작은 물체 입력 비율을 높이지만 배경을 잘못 포함할 수 있습니다. `masks_raw`도 `--small-objects` 모드에서는 추적 영역 선택을 거친 마스크이며 SAM의 미필터 원시 출력은 아닙니다.
- 현재는 파일 영상을 처리합니다. 실시간 카메라, 음성 보존, 중간 프레임 재선택, 새 배경 합성은 제외했습니다.
- 영상은 MP4 출력에 맞게 가로·세로가 짝수여야 합니다. 긴 영상은 메모리·저장 공간과 처리 시간이 늘어납니다.
- 입력 영상은 프레임 수 메타데이터가 있어야 합니다. 중도 디코딩 실패나 프레임 수 불일치가 있으면 정상 완료로 처리하지 않고 오류를 냅니다. 메타데이터가 부정확한 파일도 거절될 수 있습니다.
- Small 모델로 먼저 실행하고 필요하면 `--model large`와 해당 체크포인트를 사용해 동일 영상·동일 선택으로 비교할 수 있습니다.
- Kaggle 자료는 사용 조건을 확인한 후 넣어야 합니다. 마스크 정답이 없는 영상만으로 IoU/Dice를 계산할 수는 없습니다. 원본 자료와 모델 가중치는 GitHub에 함께 올리지 않습니다.

프로젝트에는 현재 실행 코드, 모델, 입력 영상과 재설치 안내를 유지합니다. 결과 파일은 실행할 때 `outputs` 폴더에 새로 생성됩니다. GitHub에는 실행 환경, 모델 가중치, 입력 영상과 결과 파일을 포함하지 않습니다.

## GitHub에 올릴 파일

실행 코드(`main.py`, `segmentation/`), 모델 다운로드 도구(`tools/`), 설치 목록, `run_sample.cmd`, VS Code 설정, 이 안내와 최신 중간보고서·첨부 PNG를 올립니다.

입력 영상, 결과 폴더, 모델 가중치, `.venv` 가상환경은 로컬에서 사용하며 `.gitignore`로 제외합니다. `input`, `outputs`, `checkpoints`에는 빈 폴더 유지를 위한 `.gitkeep`만 업로드합니다. 따라서 저장소를 내려받은 뒤 위 준비 절차로 실행 환경과 모델을 구성하고, 직접 준비한 영상을 `input/sample.mp4`로 넣어야 실행됩니다.

VS Code의 ▶ 버튼은 `main.py`를 열고 사용합니다. F5의 기본 실행도 같은 `input/sample.mp4`를 사용하며, 처리 결과는 매번 새로운 `outputs/selected-…` 폴더에 저장됩니다. 과거 실험 결과에 의존하던 별도 교통 영상 실행 파일은 정리했습니다.

과거 결과·검토 기록은 정리 시 별도 보관 폴더로 옮겼습니다. 이 정리는 파일 구성과 업로드 범위를 정돈한 것이며 모델의 추적 정확도나 처리 속도를 높이는 변경은 아닙니다.
